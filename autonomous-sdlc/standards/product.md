# Product Standards

- Treat `spaces_prd.docx` and `spaces_ux_guide.docx` as the current product source material.
- The repository currently models two surfaces: `spaces_final.html` for the guest or member experience and `spaces_host.html` for the host experience.
- New behavior should be tied to a named user need, not added as decorative scope.
- When requirements change, update the feature spec first and then adjust the prototype.
- Keep flows easy to demo. Favor clear, visible behavior over hidden system complexity.
- If a change affects both guest and host journeys, call that out explicitly in `spec.md` and `plan.md`.
