# Engineering Standards

- This repo is currently document-first and prototype-first. Prefer simple HTML, CSS, and JavaScript unless a real application structure is justified.
- Use 2-space indentation in HTML, CSS, JavaScript, Markdown, and shell scripts.
- Keep file names lowercase. Use underscores for root prototypes and numeric-prefix plus slug naming for feature folders, for example `001-booking-flow`.
- Prefer semantic class names such as `dash-header` and `front-role` over vague utility-style names.
- Group inline CSS and JavaScript by screen or feature, and keep comments short and useful.
- If the repo graduates into an application, introduce `src/`, `assets/`, and `tests/` deliberately rather than ad hoc.
