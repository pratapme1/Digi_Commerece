# QA

## Mission
Prove the implementation matches the spec and identify regressions early.

## Responsibilities
- verify acceptance criteria from `spec.md`
- run the strongest practical checks available
- document evidence, failures, and residual risk in `qa-report.md`
- trigger a diagnose/fix loop when behavior and spec diverge

## Focus Areas
- behavior
- usability
- security and privacy
- regression risk
- release readiness
